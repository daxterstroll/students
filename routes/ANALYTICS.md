# Аналітика (/admin/analytics)

Нова сторінка в меню Адміністрування → **«Аналітика»**, новий файл `routes/analytics.py` + `templates/analytics.html`.

## Що показує

**KPI-картки:** активних студентів, активних груп (+ скільки в архіві), середній розмір групи, кількість користувачів системи.

**Заповненість даних студентів** (прогрес-бари по кожному розрізу окремо):
- особисті дані (ті самі 8 полів, що вже рахуються на головній сторінці списку студентів);
- оцінки з предметів (% заповнених оцінок відносно кількості предметів групи);
- практика/курсові/атестація;
- військовий облік - окремо: у скількох % студентів взагалі є запис, і наскільки він заповнений у тих, у кого є;
- % студентів з доданим документом про освіту;
- % студентів з призначеним номером диплома / номером додатка.

**Готовність до генерації документів** - комбінована оцінка (особисті дані + оцінки + документ про освіту + номер диплома), розподілена на 4 категорії: повністю готові / майже готові / частково / тільки почали.

**Студенти по групах** - список груп з кількістю активних студентів (стовпчикова діаграма).

**За формою навчання і ступенем** - розподіл студентів (Денна/Заочна, Бакалавр/Магістр).

**Групи по роках вступу** (тільки для адмінів) - скільки груп набрано в кожному році.

**Якість оцінок:**
- розподіл усіх виставлених оцінок за шкалою ECTS (A/B/C/D/E/Незадовільно);
- кількість студентів, що мають право на диплом з відзнакою (та сама формула, що й у `gen_docx.py`: ≥75% оцінок «A», без «D»/«E», атестація на «A»).

**Шаблони документів** (тільки для адмінів) - усього/тільки для адміна/приховано.

## Технічні рішення

- **Усі метрики рахуються прямими SQL-запитами до бази**, а не парсингом файлу логів (`app.log`) - лог-файл ротується, формат повідомлень може змінюватись з часом, і надійно витягти з нього точну статистику неможливо. База даних - єдине надійне джерело.
- **Визначення "заповненості" студента узгоджене** з тим, що вже показується на головній сторінці списку студентів (`students.py`, `student_list()`) - той самий список із 8 полів для особистих даних і 9 полів для військового обліку. Якщо колись зміните цей список там - варто продублювати зміну і в `analytics.py`.
- **Формула права на відзнаку узгоджена** з `gen_docx.py` (`diploma_with_honor_text`).
- **Розмежування доступу**: адміністратор бачить усе; користувач з правом `analytics`, але без адмінських прав, бачить статистику лише по своїх групах (`session['group_ids']`) - кількість користувачів системи, розбивку по роках вступу і статистику шаблонів для нього приховано (це загальносистемні, а не "його" дані).
- Нове право доступу `analytics` (видається через Користувачі та права).
- **Немає єдиної таблиці "активностей"** - практики/курсові/атестації зберігаються в окремих таблицях (`practices`, `courseworks`, `attestations`) з єдиною таблицею оцінок `activity_grades` (стовпець `entity_type` розрізняє тип). Це враховано окремо при підрахунку - на відміну від першої чорнової версії, де я помилково очікував неіснуючу таблицю `activities`.

## Перевірено
Побудував реалістичну тестову базу з точною схемою (2 активні групи + 1 архівна, 4 студенти з різним рівнем заповненості - від повністю заповненого відмінника до майже порожньої картки) і прогнав повний функціональний тест через Flask:
- правильна кількість активних студентів і груп (архівна група коректно виключена звідусіль);
- правильний підрахунок студента з правом на відзнаку (1 з 2, у кого є оцінки - другий коректно виключений через оцінку "D");
- розмежування доступу: не-адміністратор з правом `analytics`, обмежений однією групою, бачить статистику **лише** по своїй групі (3 студенти замість 4 загальних), дані іншої групи в його версії сторінки відсутні.

## Додатково реалізовано (за запитом)

**Загальне:**
- Перемикач «Враховувати архівні групи в статистиці» (за замовчуванням вимкнено).
- Прогноз випуску по роках (та сама формула end_year, що й у документах).
- Заповненість по кожній групі окремо (таблиця), а не лише загальний середній показник.
- Рейтинг предметів за середнім балом - топ-5 найскладніших і топ-5 найлегших.
- Список студентів "групи ризику" (є хоч одна оцінка D/E/Незадовільно) - з конкретним предметом/активністю.
- Перевірка цілісності: сума кредитів предметів+активностей групи vs кредити програми - список розбіжностей.
- Перевірка: групи, для яких немає відповідного запису в «Акредитаціях».
- Перевірка: дублікати номерів диплома / додатка серед студентів.

**По конкретному студенту:**
- Список саме тих предметів, з яких немає оцінки (не лише кількість).
- Порівняння середнього балу студента із середнім по його групі.
- Зароблені кредити (сума кредитів предметів із позитивною оцінкою) проти кредитів програми групи.

**Доступ**: підтверджено явним тестом - користувач без права `analytics` отримує редірект і не бачить сторінку взагалі; звичайний користувач із виданим правом бачить лише свої групи і не бачить адміністративних розділів (перевірки цілісності, дублікати, кількість користувачів).

## Перевірено (додатково)
Розширив тестову базу сценаріями саме під нові перевірки: розбіжність кредитів (навмисно занижена сума), група без акредитації, дублікат номера диплома між двома студентами. Усі три перевірки коректно спрацювали. Індивідуальний перегляд перевірено для трьох різних студентів: із повним набором оцінок (список пропусків порожній), з частковим (список пропусків непорожній), і з жодної оцінки (усі предмети в списку пропусків). Повторно прогнав повний попередній набір тестів (архів, безпека доступу за групами) - без регресій.

## Файли
- `routes/analytics.py` - новий, увесь розрахунок метрик.
- `routes/admin.py` - нове право `analytics`.
- `app.py` - реєстрація нового blueprint.
- `templates/analytics.html` - нова сторінка (прогрес-бари на чистому CSS, без сторонніх бібліотек графіків).
- `templates/layout.html` - посилання в меню (десктоп + мобільна версія), одразу після «Логування».
